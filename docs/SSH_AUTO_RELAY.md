# SSH через Hub без настройки адресов узлов

Начиная с версии агента 0.3.35, установленный и зарегистрированный агент сам
открывает исходящий защищённый WebSocket к Hub. Это работает на Windows и Linux.
Публичный IP, открытый порт, Cloudflare Tunnel и отдельный SSH-шлюз на узле не
нужны. Hub сопоставляет соединение с `node_id`, который агент подписывает своим
ключом регистрации. В списке узлов владелец выбирает узел и нажимает «SSH».

Агент поднимает SSH-сервер только на `127.0.0.1` со случайным портом. При
запуске он создаёт временные ключи сервера и клиента; клиент проверяет ключ
сервера по точному pin, сервер допускает только этот клиентский ключ. Вход
через этот SSH ведёт в CITADEL Restricted SSH Console с фиксированными командами
чтения. Произвольная shell-команда и доступ к файлам через SFTP не разрешены.

Worker проверяет подпись узла и выдаёт владельцу короткоживущий билет для
выбранного узла. Durable Object этого узла передаёт байты между браузером и
агентом. Время сеанса ограничено 30 минутами; билет одноразовый. Ни ключи SSH,
ни токен владельца не отправляются в браузер или Durable Object. Другой узел
получает другой Durable Object и не может подменить выбранный `node_id`.

После публикации Worker и обновления агента до 0.3.35 в Hub должно появиться
«Агент узла подключён. Можно открыть SSH». Пока узел выключен или обновление
ещё не дошло до него, Hub показывает «Агент узла ещё не подключился к
SSH-каналу». Никакого ручного ввода адреса, пользователя или ключей нет.

Первое подключение и выдача билета всё ещё требуют работоспособной D1:
проверяется регистрация узла и право владельца. Если D1 достигла лимита
записей, исправление этого лимита остаётся отдельной задачей; соединение само
по себе не снимает ограничение D1. Уже установленный агент при обновлении
ставит две закреплённые зависимости Python автоматически, если их ещё нет.
